# Mock Interview

## Round 1 — Fundamentals

1. Design a highly available web application on AWS.
2. Explain private subnet internet egress.
3. Explain IAM role vs access key.
4. Explain container image lifecycle.
5. Explain Kubernetes service discovery.

## Round 2 — Hands-on troubleshooting

1. A pod cannot schedule.
2. An application returns 502 behind an ALB.
3. Jenkins queue keeps growing.
4. Terraform reports unexpected changes.
5. Application latency increases but CPU is normal.

For every scenario, say: what you inspect → what evidence you expect → what you change → how you verify → how you prevent recurrence.

## Round 3 — Senior design

1. Design multi-AZ EKS for a critical service.
2. Design CI/CD with security gates and rollback.
3. Move deployment from Jenkins push to GitOps.
4. Design an internal developer platform for 100 services.
5. Reduce cloud cost without reducing SLO compliance.

## Round 4 — Modern platform / AI

1. How would you safely expose infrastructure tools to an AI agent?
2. How would you observe an AI inference platform?
3. How would you control AI workload spend?
4. What belongs in a golden path?
5. When should a platform team build an abstraction rather than expose a raw cloud/Kubernetes API?

## Self-review rubric

Review each answer for:

- Technical correctness
- Diagnosis sequence
- Security awareness
- Reliability thinking
- Cost awareness
- Trade-off clarity
- Verification step
- Prevention step
- Communication

A strong answer explains why, not only what.
